# 작업 목록: <기능 이름>

- 입력: `spec.md`, `plan.md`
- 형식: `- [ ] T001 [P] [US1] 설명 (경로)`
  - `[P]`: 다른 파일을 건드리고 앞 작업에 의존하지 않아 병렬로 할 수 있음
  - `[US1]`: `spec.md`의 시나리오 번호
  - 설명에는 정확한 파일 경로를 쓴다

> 아래 예시 작업은 지우고 실제 작업으로 바꾼다. 시나리오 단위로 묶어서 시나리오 하나가 끝날 때마다 따로 검증한다.

## 1단계: 준비

- [ ] T001 <프로젝트 구조, 의존성, 설정> (<경로>)

## 2단계: 기반

여러 시나리오가 함께 쓰는 것. 이 단계가 끝나기 전에는 시나리오 작업을 시작하지 않는다.

- [ ] T002 <공통 모델, 설정, 에러 처리 등> (<경로>)

**체크포인트**: 기반 완료

## 3단계: 시나리오 1 — <제목> (P1, MVP)

- 목표:
- 단독 검증:

- [ ] T003 [P] [US1] <실패하는 테스트 작성> (<tests 경로>)
- [ ] T004 [US1] <구현> (<src 경로>)
- [ ] T005 [US1] <검증 실행: `<명령>`>

**체크포인트**: 시나리오 1만으로 동작하고 검증이 끝났다

## 4단계: 시나리오 2 — <제목> (P2)

- 목표:
- 단독 검증:

- [ ] T006 [P] [US2] <실패하는 테스트 작성> (<tests 경로>)
- [ ] T007 [US2] <구현> (<src 경로>)
- [ ] T008 [US2] <검증 실행: `<명령>`>

**체크포인트**: 시나리오 1, 2가 각각 동작한다

## 마무리

- [ ] T0NN 문서 갱신 (`README.md`, `docs/memory.md`)
- [ ] T0NN 전체 검증 (`<명령>`)

## 순서

- 준비 → 기반 → 시나리오(P1 → P2 → …) → 마무리
- 기반이 끝나면 시나리오끼리는 서로 기다리지 않고 진행할 수 있어야 한다
- 테스트가 있는 작업은 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다
- 작업 하나나 논리적 묶음이 끝날 때마다 검증한다
