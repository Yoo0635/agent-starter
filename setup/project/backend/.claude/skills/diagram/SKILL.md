# 다이어그램으로 다시 설명

이 세션에서 물어봤던 걸 잘 이해하지 못해서, 흐름도와 순서도를 보고 쉽게 이해하려고 쓰는 스킬이다.
기존 내용보다 더 쉽게 말하고, 다른 것에 비유하지 않는다.

## 무엇을 설명할지

1. 사용자가 대상을 말했으면(명령어 뒤에 적은 내용 포함) 그것을 설명한다.
2. 말하지 않았으면 직전 답변의 내용을 설명한다.

## 그리는 것

- **흐름도**: 무엇이 무엇으로 이어지는지 (요청 → 파일, 파일 → 파일, 폴더 → 복사 위치)
- **순서도**: 일이 일어나는 순서와 갈림길 (1단계 → 2단계 → 조건에 따라 나뉨)
- 둘 중 하나만 의미가 있으면 하나만 그린다.

## 그리는 법

- ```` ```text ```` 코드 블록 안에 글자로 그린다. 화살표는 `→`, `↓`, 갈림길은 `├─ 예`, `└─ 아니오`로 쓴다.
- 칸 하나에는 한 가지만 쓴다. 이름은 실제 파일명, 경로, 명령어 그대로 쓴다.
- 다이어그램 하나에 단계는 7개 이하로 둔다. 넘으면 나눠 그린다.

## 설명하는 법

- 다이어그램 아래에 단계마다 한두 문장으로 설명한다.
- 기존 설명보다 쉬운 말을 쓴다. 처음 나오는 용어는 바로 뒤에 뜻을 적는다.
- 비유하지 않는다. 실제 파일, 명령, 동작으로만 설명한다.
- 기존 답변을 그대로 반복하지 않는다.

## 예시

"문서 작성 부탁하면 어떻게 되는지 이해 안 돼"

```text
"ADR 써줘"
   ↓
templates/adr/adr-TEMPLATE.md 읽기
   ↓
docs/adr/에 같은 결정의 ADR이 있나?
├─ 아니오 → 다음 번호로 템플릿을 복사해서 새로 작성
└─ 예     → 기존 파일을 수정
```

1. 에이전트가 `templates/adr/` 안에서 ADR 양식 파일을 읽는다.
2. `docs/adr/`에서 같은 결정의 ADR이 있는지 본다.
3. 없으면 다음 번호로 양식을 복사해 새로 쓰고, 있으면 그 파일을 고친다.
