# 기능 문서 작성

## 어느 단계인지 정하기

1. 사용자가 말한 기능의 폴더가 `docs/spec/`에 있는지 본다.
2. 없으면 새 폴더를 만들고 `spec.md`부터 쓴다.
3. 있으면 폴더 안에 아직 없는 첫 문서를 쓴다. 순서는 `spec.md` → `plan.md` → `tasks.md`(+ `worklog.md`)다.

## 새 폴더 만들기

1. `docs/spec/`에서 가장 큰 `NNN`에 1을 더한다. 폴더가 없으면 `001`이다. 지운 번호는 다시 쓰지 않는다.
2. 기능 이름은 영어 kebab-case로 짧게 짓는다 (예: `002-payment`).
3. 폴더 이름을 사용자에게 보여주고 확인받은 뒤 만든다.

## 문서 쓰기

1. `templates/spec/<문서>-TEMPLATE.md`를 복사한다.
2. 섹션 제목과 순서는 바꾸지 않고 내용만 채운다. 템플릿 안의 안내문(`>`)을 따른다.
3. 모르는 것은 추측하지 않고 `[확인 필요]`로 표시한다.
4. 한 번에 한 문서만 쓴다. 다 쓰면 사용자에게 보여주고 다음 단계로 갈지 묻는다.

## 단계별 규칙

- `spec.md`: `[확인 필요]`가 남아 있으면 `plan.md`로 넘어가지 않고, 질문 목록을 사용자에게 보여준다.
- `plan.md`: 새 엔터티나 필드가 생기면 `docs/design/db.md`를, API가 바뀌면 `docs/design/api.md`를 함께 갱신한다. 되돌리기 어려운 결정이 있으면 adr 스킬을 쓴다.
- `tasks.md`: 만들 때 같은 폴더에 `worklog.md`도 템플릿으로 만든다.
